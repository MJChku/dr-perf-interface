# One-round request-admission findings

The source-only prediction is frozen in `measurements/submissions/round-00.json`. Exactly one measurement round was run, with three configurations: (reqs=4, passes=4,4, max_tokens=1), (16,16,16,1), and (16,16,16,4). All returned zero; consolidated status is `ok`. No optimization or workload behavior change was made. Observation edits wrap six admission helpers. Original reports, raw counts and wait sidecars remain under `measurements/round-01`; `evidence.csv` retains 197 raw region/state rows, including counts, own means, own minima/maxima, and parent contexts.

## Revised entry-state candidate

For `admission.request`, propose `int(cached_load_custom_logitsprocs.cache_info().currsize == 0)` **only for the fixed `model_config.logits_processors=None` key used here**. This queries existing cache state without replaying validation or plugin loading. Source `SamplingParams.verify` calls `_validate_logits_processors`, which calls `validate_logits_processors_parameters`; the latter uses this LRU cache. A miss calls `_load_custom_logitsprocs`, which calls `_load_logitsprocs_plugins` and `importlib.metadata.entry_points(group=LOGITSPROCS_GROUP)`. Engine initialization invokes the uncached loader, so it does not fill this validation cache. This is a concrete refinement of the initially anticipated cold/cache uncertainty, not an established causal discovery. Cache state was not recorded, and the report's leading native Python functions do not independently prove which caller caused the spike. Its explanatory coefficient and sufficiency remain unverified; another run recording cache state and/or a narrower plugin-discovery region would be required. For arbitrary cache keys, `currsize == 0` does not identify all misses.

No stronger new PCV is claimed for allocator residuals or tokenizer cold initialization: their entry-visible representations were not established in this round. Report residual attribution suggests where a future narrower observation should go; it does not justify replacing semantic size expressions with measured work.

## Evidence boundaries

All instruction numbers describe CPU work. Supervisor wall times (28.96, 116.63, 143.64 seconds) and printed inference times include model execution and instrumentation; they are not admission latency or speedup estimates. Parent own costs exclude marked children; overlapping parent/child totals must not be added. The hash helper is shared with generation, so consolidated hash totals include calls outside admission; parent-qualified raw comparisons above isolate admission.

The workload fixes model, ASCII sentence, hash block size, sampling fanout, no LoRA, no multimodal inputs, and no structured output. Prompt token count and resident index are coupled. Untested Unicode/text composition, other hashes, block sizes, custom processors, exceptions, streaming and n>1 remain outside validation scope. Requested generation changes do alter model execution, which was deliberately not marked.

The report records 5654 uncovered wait observations and `wait_check_status=unexplained`; no semantic wait claims were submitted, so this does not establish synchronization dependencies. Its lexical source-coverage scanner reports zero marked lines because annotations use the `_admission_region` import alias, while runtime evidence contains all six regions and 72 admission invocations. This scanner limitation does not imply the workload was unmarked at runtime. No environment failure occurred; default vLLM emitted CPU/backend fallback warnings, preserved in each output file.
