# PCV discovery results

Submitted round 0 from source alone, then used all three authorized measurement rounds (six processes each), updating and submitting hypotheses after each round. All 18 workloads returned successfully. No optimization or direct workload execution was performed; source edits only mark the native call and compute entry-state counters.

The main discovery is cumulative prefix subtree size. A homogeneous left-associated binary chain with k operators has PCV k*(k+1)//2, alongside its linear term/node count. A shape-2 method chain has two primary trailers per method and PCV t*(t+1)//2 with t=2*n. These expressions use source counts available before native parsing and do not replay the parser. Shape changes require distinct coefficients: call chains cost much more than addition or union chains at the same n.

Relevant sources are native/libcst/src/parser/grammar.rs:973 (bitwise_or), :1004 (sum), :1060 (primary), all cache_left_rec rules; native/libcst/src/nodes/expression.rs:448 and :661 onward store boxed recursive expressions; native/libcst_derive/src/cstnode.rs:118-121 and :205-208 derive deep Clone. Native report attribution connects the quadratic PCV to DeflatedExpression::clone, DeflatedAttribute::clone, allocation, free, and drop work. Inflation and Python conversion visit the final tree, contributing linear node-population work (native/libcst/src/lib.rs:35-47; native/libcst_derive/src/into_py.rs:83-104). Python grammar conversion functions are inactive on this native path.

Saved-total instruction fits (analysis.json, generated by analyze_results.py) provide a separate check. Affine models in n and prefix size have mean absolute relative errors of 0.214%, 0.805%, and 0.445% for addition, calls, and union. Training only on the first five points predicts the largest sixth point with relative error 0.397%, 0.995%, and 1.097%, respectively. Linear-only models miss those held-out points by 24.8%, 41.0%, and 33.3%. Total-cost fits are not the same as DrPerf's basic-block residual test; small total errors do not erase allocator residual.

Limits: one observation per configuration; no arbitrary Python syntax, balanced trees, long identifiers independent of n, or separate tokenization/inflation native-region measurements. Input length is a source-supported scanning PCV but is correlated with n here and lacks an independently measured coefficient. Alternating attributes/calls have different node weights, absorbed by coefficients; exact PEG cache clone multiplicities are not proved. Call-chain residual is concentrated in allocator internals and cache rehashing. Reports include unexplained native lock observations; no semantic wait dependency or latency law is claimed. Instruction growth does not establish wall-time growth. Startup/import work outside the marked native call is excluded. Measurement artifacts remain under measurements/round-01 through round-03.
