# Opt-in Inferix RoPE frequency reuse

The drperf baseline records 2,100 `inferix_causal_rope` calls and 749,846,300 exclusive CPU instructions during the measured 21-frame generation. Each call rebuilds the same complex frequency grid with `split`, `expand`, `cat`, and `reshape` for the current frame offset. Query and key do this separately at every block and denoise step.

`rope_frequency_cache.patch` reuses this immutable grid, keyed by source tensor identity and version, grid dimensions, head width, frame offset, and CUDA stream. It retains the source tensor and producing stream and is bounded to eight entries (about 38 MiB for eight 4,680-token, 64-complex-value grids). It stays disabled unless `INFERIX_ROPE_FREQ_CACHE=1` is set before importing Inferix, and it never caches when autograd is enabled. The model-owned `self.freqs` is assigned or moved to a device but is not modified in place.

`prepare_cpu_rope_cache.py` copies `out/causal-video/Inferix-optimized` to `out/causal-video/Inferix-cpuopt` and applies the patch. The prepared tree is already present and is staged, source only, on both the GX and native hosts. `native_run.py --rope-cache` selects that tree, sets the environment flag, and runs `cpu_rope_entry.py`; for `--validate` it keeps the semantic capture entry while passing the flag through. The wrapper calls the frozen `inferix_runner.main()` and then adds `optimizations.rope_frequency_cache` to `report.json`, including hits, misses, evictions, entries, and live cache bytes. It never moves workload timers or profiling gates.

Syntax passed. A CPU inference-mode parity check compared original and cached `causal_rope_apply` outputs exactly at frame offsets 0, 1, and 2, including repeated calls. A separate CPU check verified invalidation after an in-place frequency edit and cache statistics; a wrapper test verified post-run report metadata. The preparation script reproduced the prepared file byte for byte.

Full native A100 validation passed with an exactly identical 63-frame video. A separate two-segment validation matched callbacks, videos, and latents exactly. In five warmed native requests, median latency was 12.688059104 s without the cache and 12.694004179 s with it: **no observed latency improvement**. Peak allocated GPU memory rose 32.56 MiB; peak reserved rose 1,286 MiB. Matched GX drperf runs counted 253,827,270 fewer RoPE-region exclusive host instructions (33.72%) and 271,783,052 fewer instructions overall (5.20%), with valid collections. These instruction reductions did not translate into a measurable native latency benefit. See [CPU results](../CPU_RESULTS.md) and [compact evidence](../evidence/inferix-cpuopt.json).

The removed `cat` operations can change GPU kernel inventory and timing. A matching native GPU profile is needed before using this variant for GX timing comparisons.
