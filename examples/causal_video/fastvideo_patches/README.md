# FastVideo worker output transfer for GX

The full FastVideo GX worker completes the model but cannot send its CUDA output tensor through PyTorch multiprocessing: `_share_cuda_()` calls `cudaIpcGetEventHandle`, while GX does not implement cross-process event completion. GX event state and stream dependencies live in a per-process map, so returning a nominal handle would risk reading output before its producer completes.

`worker_cpu_output.patch` is an opt-in source adaptation selected by `FASTVIDEO_WORKER_CPU_OUTPUT=1`. The worker copies the fp32 output to a shared CPU tensor, computes the same `(src * 255).clamp_(0, 255).to(torch.uint8)` on its GPU as the parent ordinarily would, and copies that uint8 tensor to shared CPU storage. Sending the CPU tensors uses PyTorch's CPU shared-memory transport and needs no CUDA IPC event. The parent uses the received fp32 tensor directly as public `samples` and the received uint8 tensor for frame-grid construction. The default path is unchanged.

This moves the two device-to-host transfers and GPU quantization from after the worker RPC to before its response. It also avoids the parent-side fp32 mirror copy and pinned output preallocation. The measured public `generate_video` call still contains model execution, VAE decode, both real transfers, GPU quantization, and frame construction, but the internal worker/parent timing split changes. Native and GX comparisons must both enable the flag and use the same source. A fresh native GPU profile is needed for the new path; prior kernel inventories and timings cannot be reused as a matched reference.

The GX `partial_sync` markers bracket the GPU worker, not the parent process. The patch moves GPU quantization and both transfers into that worker interval, but final frame-grid construction remains in the parent after the worker responds. The worker virtual duration therefore omits that parent CPU work and must not be presented as the full public-call latency. The native public-call timer still includes it.

The patch applies to the pinned FastVideo source plus the separate diagnostic metadata adaptation. `prepare_fastvideo_metadata.py` recreates the isolated source tree. No GX event stub is changed. Syntax, CPU shared-tensor algebra, and a live worker-to-parent shared-tensor pipe round trip passed locally. The patched native run produced a finite 81-frame video whose saved fp16 tensor SHA256 exactly matched the current-environment original-source reference; a full GX generation also completed. Full fp32 tensor and frame-grid bitwise identity have not been established.
